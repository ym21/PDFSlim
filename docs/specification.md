# PDFSlim 仕様書

- Version: 0.1
- Target OS: Windows 10 / 11
- Application type: ローカルデスクトップアプリケーション
- Primary implementation language: Python

## 1. 概要

PDFSlim は、スキャンPDFや画像を多く含むPDFを対象に、画質とファイルサイズのバランスをユーザーが調整しながら軽量化できる Windows 向けデスクトップアプリケーションである。

処理はすべてローカルPC内で完結し、PDFや画像データを外部サーバーへ送信しない。

## 2. 目的

- スキャンPDF、画像中心PDFのファイルサイズを削減する
- 専門知識がなくてもプリセットから簡単に圧縮できるようにする
- 必要に応じて DPI、JPEG品質、カラー方式などを細かく調整できるようにする
- 機密文書でも利用しやすいローカル完結型とする
- 元PDFのページ構成を可能な限り維持する

## 3. 想定ユーザー

- 紙資料をスキャンしてPDF保存しているユーザー
- メール添付やアップロード制限のためPDFサイズを小さくしたいユーザー
- 写真や画像の多い資料を軽量化したいユーザー
- 外部クラウドへ文書をアップロードしたくないユーザー

## 4. 対象範囲

### 4.1 主な対象

- スキャナーで作成したPDF
- スマートフォン等で撮影した画像から生成されたPDF
- 写真を多く含むPDF
- 画像として保存された文書PDF

### 4.2 MVPでは優先しない対象

- CAD由来の複雑なベクターPDF
- Illustrator等から生成されたベクター主体PDF
- フォント埋め込みが主な容量増加要因となっているPDF
- 動画、音声、3D等を含む特殊PDF

## 5. 動作方針

### 5.1 完全ローカル動作

- インターネット接続を必要としない
- PDFデータを外部へ送信しない
- 圧縮処理、画像変換、PDF再構築はすべてローカルで実行する
- アプリ利用時にアカウント登録を要求しない

### 5.2 元ファイルの保護

- デフォルトでは元PDFを上書きしない
- 出力先を明示的に指定可能とする
- 同名ファイルが存在する場合は上書き確認または自動リネームを行う

## 6. 主要機能

### 6.1 PDF読み込み

- ファイル選択ダイアログからPDFを追加できる
- ドラッグ&ドロップに対応する
- 複数PDFをまとめて追加できる
- 読み込んだPDFについて以下を表示する
  - ファイル名
  - 元ファイルサイズ
  - ページ数
  - 保存先
  - 処理状態

### 6.2 圧縮プリセット

以下のプリセットを提供する。

#### 高画質

- 目安DPI: 250〜300
- JPEG品質: 80〜90
- カラー維持
- 印刷を想定

#### バランス

- 目安DPI: 150〜200
- JPEG品質: 65〜80
- カラー維持
- 標準プリセット

#### サイズ優先

- 目安DPI: 100〜150
- JPEG品質: 40〜65
- 必要に応じてグレースケール化
- 画面閲覧、メール添付向け

#### 文書

- 文字中心のスキャン文書向け
- グレースケールまたは白黒2値化
- 白黒文書では CCITT Group 4 または JBIG2 等を利用可能とする
- 写真を含む場合は極端な2値化を避ける

### 6.3 詳細設定

ユーザーはプリセットを選択したうえで、以下を個別に変更できる。

#### 解像度

- 元解像度を維持
- 300 DPI
- 200 DPI
- 150 DPI
- 120 DPI
- 96 DPI
- 任意値入力

元画像の解像度が指定値以下の場合、原則としてアップスケールしない。

#### JPEG品質

- 1〜100で調整可能
- 推奨範囲をGUI上で分かりやすく表示する

#### カラーモード

- カラー維持
- グレースケール
- 白黒2値

#### 画像処理

- ダウンサンプリング ON/OFF
- JPEG再圧縮 ON/OFF
- グレースケール化 ON/OFF
- 白黒2値化 ON/OFF
- 自動余白除去 ON/OFF
- PDF内部最適化 ON/OFF
- メタデータ削除 ON/OFF

### 6.4 圧縮前分析

可能な範囲でPDF内部を分析し、以下を表示する。

- ページ数
- 総ファイルサイズ
- 画像数
- 画像中心PDFかどうか
- 主要画像のおおよその解像度
- カラー / グレースケール / 白黒の傾向

将来的には、画像がファイルサイズ全体に占める割合を推定して表示する。

### 6.5 圧縮処理

基本パイプラインは以下とする。

1. PDFを読み込む
2. ページと画像リソースを解析する
3. 圧縮設定を決定する
4. 対象画像を抽出またはデコードする
5. 必要に応じてリサイズする
6. 必要に応じてカラー変換する
7. 適切な方式で画像を再圧縮する
8. PDFへ画像を再配置する
9. 不要なPDFオブジェクトを削除する
10. PDF構造を最適化する
11. 別ファイルとして保存する
12. 元サイズと圧縮後サイズを比較して表示する

### 6.6 処理結果表示

圧縮完了後、以下を表示する。

- 元ファイルサイズ
- 圧縮後ファイルサイズ
- 削減サイズ
- 削減率
- 出力先
- 処理時間

例:

```text
Original:   48.2 MB
Compressed: 12.7 MB
Reduced:    35.5 MB (73.7%)
```

### 6.7 バッチ処理

- 複数PDFをキューへ追加できる
- 同じ圧縮設定を複数PDFへ適用できる
- ファイルごとの進捗を表示する
- 全体進捗を表示する
- 1ファイルで失敗しても、他の処理を継続できる設計とする

## 7. 圧縮方式

### 7.1 画像ダウンサンプリング

スキャンPDFでは最優先の圧縮方式とする。

高解像度の画像を目的に適したDPIまで縮小する。

例:

```text
600 DPI -> 200 DPI
300 DPI -> 150 DPI
```

元解像度が設定値より低い場合は変更しない。

### 7.2 JPEG再圧縮

写真やカラー画像をJPEGで再エンコードする。

- 高画質: Quality 80〜90
- バランス: Quality 65〜80
- サイズ優先: Quality 40〜65

JPEGの再圧縮による世代劣化を考慮し、不要な再圧縮を避けられる設計とする。

### 7.3 グレースケール化

カラー情報が不要な文書に対してRGB等からグレースケールへ変換する。

主な対象:

- 契約書
- 請求書
- 紙文書
- 書籍
- 資料コピー

### 7.4 白黒2値化

文字と線画が主体の文書向けに白黒2値化を行う。

候補圧縮方式:

- CCITT Group 4
- JBIG2

JBIG2を利用する場合、文字の誤置換などのリスクを避けるため、MVPでは lossless モードを優先する。

### 7.5 余白除去

スキャン時に生成された不要な余白や黒枠等を検出し、画像データから除去する。

ただし、ページサイズそのものを変更するか、ページサイズを維持したまま画像のみ最適化するかを設定可能にする余地を残す。

MVPでは自動余白除去をオプション機能とする。

### 7.6 PDF内部最適化

以下を実施する。

- 未参照オブジェクトの削除
- 重複オブジェクトの整理
- ストリーム圧縮
- Incremental Update等により残った不要データの整理

画像主体PDFでは画像圧縮ほどの効果は期待しないが、画質劣化なしで削減可能なため基本処理として利用する。

### 8.2 ファイル一覧

列候補:

- ファイル名
- 元サイズ
- ページ数
- ステータス
- 圧縮後サイズ
- 削減率

操作:

- 削除
- すべて削除
- エクスプローラーで開く

### 8.3 詳細設定UI

初心者向けUIを維持するため、基本画面ではプリセットを中心にする。

詳細パラメータは「詳細設定」を展開した場合にのみ表示する。

### 8.4 進捗表示

処理中は以下を表示する。

- 現在処理中のファイル名
- 現在ページ / 総ページ数
- ファイル単位の進捗バー
- 全体進捗バー
- キャンセルボタン

GUIがフリーズしないよう、圧縮処理はGUIスレッドとは別スレッドまたは別プロセスで実行する。

## 9. エラー処理

以下をユーザーへ分かりやすく通知する。

- PDFが壊れている
- パスワード付きPDFである
- 書き込み権限がない
- 保存先容量が不足している
- PDF内部構造を解析できない
- 一部画像を再圧縮できない
- 圧縮後ファイルが元ファイルより大きくなった

圧縮後ファイルが元ファイル以上のサイズになった場合は警告し、元より小さくならなかったことを明示する。

## 10. 技術構成

### 10.1 推奨構成

第一候補:

- Python 3.12+
- PySide6
- pikepdf
- Pillow
- NumPy（画像判定等で必要になった場合）
- OpenCV（自動余白除去や画像解析が必要になった場合）
- PyInstaller または Nuitka

### 10.2 GUI: PySide6

PySide6を推奨する。

理由:

- Windowsデスクトップアプリに適している
- QtベースでUI部品が豊富
- ドラッグ&ドロップやテーブル、進捗表示を実装しやすい
- Pythonから利用可能
- GUIと処理ロジックを分離しやすい

Tkinterよりも本アプリのような実用デスクトップアプリに向いている。

### 10.3 PDF操作: pikepdf

PDF内部構造の読み書き・最適化を担当する。

想定用途:

- PDF読み込み
- オブジェクトアクセス
- 画像リソース操作
- 不要オブジェクト整理
- PDF再保存

### 10.4 画像処理: Pillow

想定用途:

- JPEG再圧縮
- リサイズ
- DPI変更
- グレースケール化
- 基本的な白黒変換

### 10.5 OpenCV

MVP必須ではない。

以下を実装する段階で導入を検討する。

- 自動余白検出
- 傾き補正
- ノイズ除去
- 文書領域検出
- 自動2値化

## 11. Python以外の選択肢

### 11.1 C# / .NET

Windows専用アプリとしては有力候補である。

メリット:

- Windowsとの統合が強い
- WinUI 3 / WPF等を利用できる
- 配布しやすい
- ネイティブ感のあるGUIを構築しやすい

デメリット:

- PDF画像処理ライブラリの選択肢がPythonほど手軽ではない場合がある
- 画像解析や実験的な処理を追加する際はPythonの方が開発しやすい

### 11.2 推奨判断

MVPは Python + PySide6 を推奨する。

理由:

- PDF・画像処理の試行錯誤がしやすい
- Pillow、OpenCV等の画像処理資産を利用できる
- 実装速度が速い
- GUIもPySide6で十分な品質を確保できる

将来的にWindowsとの深い統合や起動速度、配布サイズが大きな課題になった場合は、C#/.NETへの移行を再検討する。

## 12. アーキテクチャ

## 15. パフォーマンス要件

- GUI操作中に圧縮処理でUIをブロックしない
- 100ページ以上のPDFを処理可能とする
- 大容量PDF処理時に全ページ画像を同時にメモリへ展開しない
- ページまたは画像単位で順次処理する
- 一時ファイルを利用する場合は処理終了時に確実に削除する
- キャンセル操作を可能にする

## 16. セキュリティ / プライバシー

- ネットワーク通信を必須としない
- PDF内容を外部へ送信しない
- 一時データもローカルのみで扱う
- 一時ファイルは処理終了後に削除する
- 元ファイルはユーザーの明示操作なしに変更しない
- アプリログにPDF本文や画像内容を保存しない

## 17. ログ

ローカルログを保存する。

記録対象:

- アプリバージョン
- 処理開始 / 終了
- ファイルパス
- 元サイズ / 出力サイズ
- 使用した圧縮設定
- エラー情報

PDF本文や画像内容そのものはログへ記録しない。

## 22. 基本方針

PDFSlimのMVPでは、高度なPDF最適化機能を網羅するのではなく、スキャン・画像中心PDFで効果の大きい以下の処理に集中する。

1. 画像ダウンサンプリング
2. JPEG再圧縮
3. グレースケール化
4. 白黒文書圧縮
5. PDF内部最適化

ユーザーには内部技術を意識させず、「高画質」「バランス」「サイズ優先」「文書」のプリセットを中心としたシンプルな操作体験を提供し、必要なユーザーのみ詳細設定を調整できる設計とする。
